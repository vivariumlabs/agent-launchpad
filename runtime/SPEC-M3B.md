## 1. Genesis orchestrator (`genesis/`, per 04)

**Package:** standalone TS package (`genesis/package.json`, ESM, vitest, viem, zod, better-sqlite3), with a `file:../runtime` style dependency ONLY for canonical primitives: `canonicalEncode`, `frozenConfigHash`, `FrozenConfigFileSchema` (hash consistency between orchestrator and runtime is load-bearing — NEVER reimplement the encoding). If file-dep wiring fights the toolchain, use a tsconfig path alias into `../runtime/src` and note it.

**Trust boundary (04 preamble, restate in genesis/README.md):** the orchestrator can deploy CVMs, seed from its funding wallet, and call `finalize`. It holds NO agent keys and cannot touch live agents. Its own key = the operational wallet (path from config; `.secrets/` pattern; never logged).

**Sequencing decision (rev 0 ruling):** 04 §1's diagram shows finalize before seeding, but 04 §2 says seed failures BLOCK finalize; the text wins. Canonical order:
`REQUESTED → DEPLOYING → AWAITING_REGISTER → SEEDING → RECONCILING → FINALIZING → LIVE`, with `FAILED(reason, step)` reachable from any step. **(rev 1)** The 24h `DEFAULT` timeout applies ONLY up to registration (post-registration auto-FAIL would strand the creator's fee — `cancel` reverts once registered); stalls after registration are operator-re-driven via `redrive --agent-id`. An agent is never tradeable (finalized) before it is fully funded — a guarantee binding on THIS orchestrator only (`finalize` is permissionless on-chain). (rev 1 additions: `preGas` leg to expectedTreasuryEOA after attestation-verify, fixing the registration-gas deadlock; `hosting` virtual leg so the first month's rental is fee-accounted per 04 §2/01 §4; remainder = fee − executed legs.)

**Components (src/):**
- `db.ts` — SQLite: `launches(agentId PK, state, requestTx, deployJobId, cvmIp, configHash, attempt counts per step, updatedAt, lastError)`, `seeds(agentId, leg, txHash, status)`, `kv`. Every transition persisted BEFORE side effects where possible; all steps idempotent by re-checking chain/CVM state first (Lifecycle.s.sol staged-guard pattern).
- `watcher.ts` — polls factory logs for `AgentRequested` (viem `getLogs`, cursor in kv; interval `pollSec 15 DEFAULT`). Emits into the state machine. ABI from `contracts/` (transcribe with source refs, same discipline as runtime abi.ts).
- `oyster.ts` — wrapper around the `oyster-cvm` CLI (child_process; binary path from config): `deploy({composePath, agentId, configHash, agentJsonPath, runtimeJsonPath, durationMin, walletKeyPath})` building EXACTLY the init params from SPEC-M3 (`agent-id:1:0:utf8:agent-<id>`, `config-hash:1:0:utf8:0x…`, `agent.json:0:0:file:…`, `runtime.json:0:0:file:…`); `ip(jobId)` via the control-plane lookup (M0 RESULTS: `GET <cp>/ip?id=<jobId>` with CP from the indexer GraphQL); `verify(ip, imageId)`. All shelling mockable via an injected `Exec` interface.
- `machine.ts` — per-agent resumable state machine. DEPLOYING: submit deploy, record jobId; retry ×3 `DEFAULT` on failure then FAILED. AWAITING_REGISTER: poll `registry.isRegistered(agentId)` + instance record matches expected (treasury EOA known only after registration — read it from the registry); also `oyster.verify` the attestation once an IP exists (04 §7 row 1: attestation invalid ⇒ retry/FAILED, never finalize). SEEDING: per-leg txs (below), each leg idempotent (skip if the seed row has a confirmed tx or the target balance already ≥ expected). RECONCILING: re-read every leg's target balance; all ≥ expected ⇒ FINALIZING; missing legs re-queue (×5 then FAILED). FINALIZING: `factory.finalize(agentId)` guarded on-chain-state (skip if already finalized). LIVE.
- `seeder.ts` — legs per 04 §2, amounts from config with `DEFAULT`s as in the doc table; **testnet profile** `DEFAULT` for s3: RH-USDG (Mock) remainder, RH ETH $2-equiv, skip OP (Farcaster deferred until funded), Base ETH+USDC only if the funding wallet holds them, Arb ETH $1, Arweave = Turbo top-up (see §3; skip if Turbo unfunded, log loudly). The funding wallet sends NATIVELY per chain (no bridging inside the orchestrator). Every tx: fee-capped, nonce-managed, receipt-awaited.
- `revival.ts` — `revive(agentId, payerInfo)`: allowed only if registry heartbeat stale > 7d (read on-chain); same deploy path, same frozen config fetched from Arweave ref recorded at genesis (config from launch db as fallback); does NOT seed (revival economics = reviver pays hosting; 04 §6) except a minimal gas top-up leg `revivalGasSeed DEFAULT $2 RH`.
- `main.ts` — argv config path, start watcher + resumer loop (re-drives all non-terminal launches every `resumeSec 60 DEFAULT`), SIGINT graceful.
- `config.ts` — zod: chain RPCs, factory/registry/usdg addresses (read `contracts/deployments/testnet-46630.json` at config-build time — a helper `configFromDeployment(manifestPath)`), walletKeyPath, releaseCompose path, seed table, oyster settings, turbo settings.

**Failure table (04 §7)** must be visibly mapped: each row → a test.

**Tests:** unit (mock Exec, mock chain via viem test transports or a MockRpc): full happy path REQUESTED→LIVE with every side effect recorded; resume-after-crash mid-DEPLOYING and mid-SEEDING (idempotence: no duplicate deploys/seed txs); attestation-invalid ⇒ never finalize; partial seed ⇒ finalize blocked, reconcile retries; timeout ⇒ FAILED; revival heartbeat-fresh ⇒ refused. **Integration (reuse runtime/test/integration/foundry.ts harness):** against the anvil stack — real `createAgent` → watcher catches the real event → mock CVM (the TEST performs registerInstance with a scripted key, standing in for the enclave) → real seed transfers (MockUSDG/ETH on anvil) → real `finalize` → assert factory/registry end state.
