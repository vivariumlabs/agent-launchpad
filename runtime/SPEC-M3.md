## 3. x402 HTTP transport + inference salt (Job J)

- **Salt (root fix for same-second action-hash collisions, replaces chat's µUSD bump):** `inference` action gains OPTIONAL `salt?: Hex` (exactly 16 bytes when present; G1-validated; engine passes it through untouched — it participates in canonicalEncode ⇒ actionHash ⇒ K3 nonce uniqueness). Deterministic construction at call sites (NO new randomness): pulse: `salt = keccak(now ‖ ":" ‖ callIndexOrPhase ‖ ":" ‖ attempt)[0..16]`; chat: `salt = keccak(now ‖ ":" ‖ walletLower ‖ ":" ‖ perRequestCounter)[0..16]` (counter = the chats-row id from the rate-limit insert — already unique). REMOVE the chat µUSD cost-bump workaround and its tests; adapt tests to salt. K1/K3 unchanged (uniqueness now comes from the hash).
- **`src/llm/x402Http.ts`**: real transport implementing the x402 exact-scheme flow: (1) POST endpoint URL (OpenAI-style chat-completions JSON per the allowlist entry's `url`); (2) on `402` parse the payment-required body (`accepts[]`: pick scheme "exact", network Base (eip155:8453), asset USDC; REQUIRE `payTo == allowlist entry.payTo` and `maxAmountRequired ≤ action.maxCostUsd` else endpoint-unhealthy + rotate — this is the SPEC-M2 §7 price-ceiling check's real hook); (3) `execute({kind:"inference", ..., salt})` (the engine approval happens HERE, per-call, quote-aware: maxCostUsd = min(estimate, quoted) — NOTE: execute() consumes budget at approval, unchanged); (4) K3 auth over the quoted amount → `X-PAYMENT` header (base64 JSON per x402 spec v1); (5) retry the POST once with the header; (6) contract-check response, record settle info from `X-PAYMENT-RESPONSE` if present. All HTTP via injected `HttpClient` interface (node fetch impl + MockHttp for tests — hygiene: network allowed ONLY in the fetch impl file, allowlist it). Timeouts (30s DEFAULT), no redirects.
- **publicSelfSummary wiring** (closes chat E3 gap): pulse LLM output schema gains optional `publicSummary` (≤ 1000 chars); when present, pulse writes kv `chat.publicSelfSummary`. Guardrail note in the tool/system prompt builder: the public summary must never quote chats.

## 3b. Config split & key binding (rev 1 ruling, closes the malicious-config hole + checklist item 5)

The single config file is split:
- **`agent.json` — FROZEN identity config** (exactly what 03 §10 anchors on-chain at genesis, plus the per-agent platform snapshot: registry/hook/router addresses, x402 allowlist, caps). Its `keccak256(canonicalEncode)` is passed as an ATTESTED init param `config-hash:1:0:utf8:0x…`; the file itself is UNATTESTED (`agent.json:0:0:file:…`). Boot recomputes the file's hash and REFUSES on mismatch with the attested value. Consequence: **keys bind to (codeHash, agentId, configHash)** — a redeploy with a modified frozen config derives useless keys; revival must supply the Arweave-published original (D10 intact). Allowlist evolution stays the 04 §4 signed-update path, verified against a platform pubkey that lives in the FROZEN config (so it's covered by the binding).
- **`runtime.json` — mutable ops config** (RPC URLs, ports, dirs, kmsUrl, x402 toggle, hosting info, dbPath...): unattested, NOT hash-bound, and must contain no spend authority — a hostile runtime.json can lie about chain state (waste/denial: txs fail on the real chain) but cannot redirect funds (destinations/caps all come from the frozen file). Boot takes `--config <agent.json> --runtime <runtime.json>`.
- `--expected-hash` stays as an optional extra check (orchestrator convenience); the attested init param is the enforcement path when `tee: true` — with tee:true and no `/init-params/config-hash`, boot REFUSES (no unbound TEE boots).

## 3c. Estimate fix (s1 follow-up finding)

`estimateMaxCostUsd` must include the output allowance: `est = ceil((promptChars/4 + maxTokens) × pricePerTok × 1.5)`, capped at maxPerCallUsd. Without it every real 402 quote (priced for max_tokens) exceeds the estimate and is price-rejected.
